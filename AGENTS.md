# AGENTS.md — GoLaz

## Project Overview

GoLaz is a pure-Go port of the [LASzip](https://github.com/LASzip/LASzip) C++ library for reading LAS and LAZ (compressed LAS) point cloud files. No CGO, no native dependencies. Writing LAS/LAZ files is not (yet) supported.

- **Public API** (`package golaz`): `reader.go`, `point.go`, `header.go`, `vlr.go`, `geotiff.go`, `options.go`
- **Decompression engine** (`package laz`): `internal/laz/` — ported C++ arithmetic coder, integer compressor, byte streams, per-version item decompressors
- **Test fixtures**: `internal/laz/testdata/las/` — mostly generated by `scripts/gen_testdata.py`, then laz-compressed with `laszip -chunk_size 100`. Notable exceptions are for LAS 1.0 and 1.1 files and other files containing WKT / Geotiff metadata.

## Build and Test

```bash
go build ./...
go test ./...        # must pass green before committing
```

## Code Style

- Standard Go conventions (`gofmt`, meaningful names, errors wrapped with `fmt.Errorf("context: %w", err)`)
- New public API goes in the `golaz` package (module root); new engine code goes in `internal/laz`
- New exported types and functions must have a godoc comment
- New `Option` functions follow the `WithSelectiveMask` pattern in `options.go`

## Testing

- Tests in the module root (`package golaz`) test the public API via `reader_test.go` and `crs_test.go`
- Tests in `internal/laz` (`package laz`) are white-box and test the engine directly
- Reference CSVs (`reference_10pts.csv`, `reference_1000pts.csv`) are the ground truth for point values — do not edit them by hand
- Several tests contain hardcoded values (bounding box, `PointsByReturn`, `FileCreationDayOfYear`) derived from the actual test files; these must generally be updated when fixtures are regenerated in a way that alters the generated points.

## Important Gotchas

- **POINT14 in-memory layout is 40 bytes, not 30** (the on-disk size). All `Offsets()` arithmetic uses in-memory sizes. GPS time is at bytes 32–39 of the in-memory buffer, not 22–29.

## Commit Messages

Use short imperative sentences (`Add selective mask test`, `Fix GPS time reset at chunk boundary`). Reference the affected file or subsystem when not obvious.
